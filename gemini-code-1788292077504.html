Инженерный тест: Linux, DevOps и SRE в экосистеме «1С:Предприятие 8»

Интерактивная самопроверка компетенций по проектированию сборочных конвейеров, изоляции раннеров в Docker, низкоуровневой диагностике памяти rphost и безаварийной оркестрации кластера на Linux.

15 практических вопросов с архитектурным разбором: защита от False Success, тонкости HASP vs *.lic, отладка утечек BSL и ловушки cgroups

Перевод инфраструктуры «1С:Предприятия» на Linux и внедрение практик непрерывной интеграции (CI/CD) кардинально меняют требования к компетенциям инженеров. Здесь больше недостаточно стандартных сценариев администрирования через GUI: на первый план выходят понимание нативной C++ архитектуры платформы, системных вызовов ядра Linux, сетевого взаимодействия службы лицензирования и детерминированной сборки конфигураций без графической оболочки.

Данная викторина создана как практический срез знаний для тех, кто строит или уже эксплуатирует высоконагруженные контуры 1С на Linux. Она охватывает как типовые ошибки новичков, так и неочевидные подводные камни, приводящие к ночным инцидентам в продакшене.

Кому будет полезен этот тест

Инженерная роль Ключевые точки проверки компетенций
DevOps / CI/CD инженеры Построение сборочных контейнеров без GUI, обход модальных окон, парсинг логов с BOM-байтами, diff-контроль исходников и предотвращение ложно-зеленых сборок (False Success).
SRE / Системные администраторы Linux Корректное монтирование программных лицензий *.lic и аппаратных HASP в Docker, мониторинг реального потребления памяти (RSS + Swap), мягкая ротация «перестарков» через systemd.
1C-разработчики и техлиды Предотвращение утечек оперативной памяти в BSL (кэшируемые модули, пулы сеансов HTTP-сервисов, временные хранилища), батчинг транзакций и профилирование через logcfg.xml.

Что проверяет викторина

  • Сборочный конвейер и CLI 1С: Разница между ring (EDT CLI), ibcmd (автономный сервер) и пакетным режимом 1cv8 DESIGNER под виртуальным фреймбуфером Xvfb.
  • 5 рубежей обороны от False Success: Как гарантировать, что ошибка компиляции или нехватка лицензий в headless-режиме не вернет код 0 в пайплайне сборки.
  • Лицензионный барьер в контейнерах: Почему docker run --net=bridge уничтожает программную лицензию, как правильно настраивать nethasp.ini и изолировать сборочные раннеры.
  • Анатомия памяти рабочих процессов: Отличие нативной C++ памяти rphost от JVM/GC, скрытые угрозы Linux Swap и различия в ротации процессов между уровнями лицензий ПРОФ и КОРП.
  • Observability и профилирование: Настройка фильтров технологического журнала (CALL, SCALL, TLOCK) и понимание ограничений C++ core dumps без PDB-символов вендора.

Практический SRE-чеклист для 1С на Linux

Используйте этот базовый чеклист для аудита надежности вашей текущей инфраструктуры разработки и эксплуатации:

Область Рискованный паттерн Надежное инженерное решение
CI/CD логи Простой grep "Ошибка" без учета BOM и кодировки лога. Конвертация через iconv в UTF-8, срез \xEF\xBB\xBF, валидация размера лога и мультиязычный regex.
HASP в Docker Широковещательный поиск ключей через broadcast по подсети. Фиксация NH_SERVER_ADDR и параметр NH_USE_BROADCAST = Disabled в nethasp.ini.
Лицензии *.lic Запуск контейнеров в режиме по умолчанию --net=bridge. Запуск со строгим --net=host и монтированием каталога /var/1C/licenses:ro для сохранения MAC-адреса.
Память на ПРОФ Попытка ограничить rphost жестким mem_limit в Docker cgroups. Отказ от жесткого OOM-килла в пользу внешней ротации через RAS API при нулевых активных соединениях.
Память на КОРП Значение --memory-excess-time = 0 (ротация фактически отключена). Установка положительного тайм-аута (например, 300 сек) для запуска фонового прогрева замещающего rphost.
